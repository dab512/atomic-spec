# Классификация изменений

Изменение описывают две независимые оси.

| Поле | Значения | Вопрос |
|---|---|---|
| `change_class` | compatible, additive, breaking | Как меняется совместимость контракта потребителя? |
| `change_type` (необязательно) | ParameterChange, RuleChange, FlowChange, ModelChange, BoundaryChange, PlatformChange | Какая часть модели или процесса меняется? |

Compatible уточняет без смены поведения; additive расширяет без нарушения прежних
гарантий; breaking меняет или удаляет контракт. Изменение параметра или платформы
может быть breaking. Необязательное поле само по себе не гарантирует совместимость
API: оценивайте существующих потребителей и обещания.

Сохраняйте ID правил, не занимайте выбывший ID другим смыслом. Обновите дату,
верните изменённый контракт в review, запишите основание и impact по parent,
смысловым и событийным связям. whereused выполняется в явной области; отсутствие
ссылок в узкой выборке не доказывает отсутствие влияния.

Новая самостоятельная ответственность или замена — повод для нового атома.
Изменение внутри прежней ответственности правит существующий атом с историей.
Ревьюеров и разрешения на публикацию определяет проект.
