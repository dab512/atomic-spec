# Начало работы

1. Прочитайте инструкции проекта и связанные атомы. Используйте реестр и
   разрешённый поиск; определите spec-root, область, ревизию и проектный Guard.
2. Скопируйте бизнес-шаблон в specs, задайте устойчивый ID и зарегистрируйте
   `ID → путь от корня репозитория` в `specs/registry.json`.
3. Опишите бизнес-контракт и пройдите Gate A. Используйте существующую архитектуру;
   новый архитектурный атом нужен только для самостоятельного нового решения.
4. Объявите AC заголовками и напишите Gherkin; пройдите Gate B и получите
   необходимое проекту согласование.
5. Создайте поведенческие тесты с разметкой в той же правке. Запустите их и
   зафиксируйте ожидаемый RED до реализации (Gate C).
6. Реализуйте поведение со ссылками на бизнес/архитектуру; доведите те же тесты
   и затронутые регрессии до GREEN (Gate D). Выполните проектную приёмку.

## Установка скилла

```sh
apm install dab512/atomic-spec --target agent-skills
```

Для закреплённой переносимой копии скачайте `atomic-spec-orchestrator-2.0.0.zip`
из GitHub Release v2.0.0 и распакуйте в `.agents/skills/`. Верхний каталог архива —
`atomic-spec-orchestrator`. Совместимость упаковки APM сохранена; установка через
живой сервис APM не входит в локальную приёмку архива.

Встроенный Git Guard применяется только без подключённого проектного экземпляра.
Для Python/JSON audit нужен Python 3.11+. Node/Go готовятся явно командой
`bash .agents/skills/atomic-spec-orchestrator/scripts/setup-guard.sh`.
До запуска прочитайте references/specguard.md скилла.
