# Изменение атомов

Классифицируйте совместимость и характер изменения, зафиксируйте прежнюю ревизию,
основание и затронутые ID. Сохраняйте установленные ID; новые обязательства получают
новые ID. При выводе правила сохраняются история и замена; его ID не переиспользуется.

Верните изменённый контракт в review. Обновляйте применимые бизнес- и архитектурные
атомы, сценарии, существующие аннотации и тесты согласованно. Повторяйте затронутые
gates: смена поведения начинается с аналитики/Gherkin, баг реализации — с
воспроизводящего теста до исправления. Согласования определяет проект.

Отдельный amendment-атом полезен для существенного изменения, когда помогает
сохранить решение; он не обязателен для каждой правки. Самостоятельная замена
получает новый атом с `supersedes`, прежний помечается deprecated.

Не переписывайте требования под выбранный алгоритм. Ошибочный тест исправляйте
по исходному требованию с обоснованием и повторной проверкой RED/GREEN.
