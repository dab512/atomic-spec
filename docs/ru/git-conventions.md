# VCS и review

Следуйте процессу проекта: VCS, ветки, коммиты и review определяются им.
Atomic Spec не требует Git, отдельной ветки на роль, PR на каждый gate или
автоматической публикации. Логический порядок артефактов — **spec → test → feat/fix**;
соответствующие коммиты полезны там, где облегчают review. Одна ветка задачи может
включать связанные бизнес- и архитектурные атомы, тесты и реализацию.

Пример: `fix(PAYMENT-001): prevent a repeated debit`.
В штатном артефакте review фиксируйте совместимость, затронутые ID, доказательства
gates и область. Необходимое согласование человеком получите до реализации;
уже данное разрешение в пределах задачи повторно не запрашивается.

Тег релиза сохраняет проверенный снимок спецификации. Этот репозиторий публикует
версионные архивы исходников и скилла. Его GitHub-процесс — архитектурное решение
этой поставки, а не обязательная конвенция для всех проектов.
