# Gates и приёмка

| Gate | Обязательное доказательство |
|---|---|
| A — аналитика | Акторы, результаты, проверяемые правила, модель/гарантии, совместимость/impact, закрытые blocking OQ; полнота без старого кода |
| B — сценарии | Для затронутых правил/гарантий есть AC или способ проверки; конкретные исходы, применимые отказы/границы/права/повторы; архитектурных контрактов хватает для тестов |
| C — RED | Автотесты запущены до реализации поведения; записаны команда, тест и ожидаемое падение по требованию; ссылки уже валидны |
| D — GREEN | Те же тесты и затронутые регрессии проходят; соблюдены оба домена требований; ожидания не ослаблены, правила не выдуманы |

До реализации получите согласование спецификации человеком, если этого требует
проект. Данное разрешение в своей области остаётся действительным. Формальная
проверка не является согласованием.

Ошибка импорта, отсутствие БД, skip/xfail, отсутствие тестов и незапущенные задания
не подтверждают RED или PASS. Минимальный каркас интерфейса допустим для запуска
теста без реализации бизнес-поведения. Верное существующее поведение сохраняет
baseline GREEN. Для бага воспроизведите RED на старом коде или изолированной
контролируемой мутации; не повреждайте общие исходники и стенды.

## Приёмка после Gate D

Фиксируйте `требование → AC → автотест → результат`, область/ревизию, команды,
факты RED/GREEN и непроверенные сценарии. Выполните проектные проверки и local-dev
сценарии. Сверьте `comments` с требованиями и реальным кодом; при изменении входов
повторите Guard. Каждый обнаруженный дефект получает регрессию.

Полный отчёт Guard устанавливает формальную корректность в выбранной области.
Бизнес-корректность, успех тестов, deployment и готовность на других архитектурах
доказываются отдельно. Отказ или незапущенная проверка остаются явными результатами.
