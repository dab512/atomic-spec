Atomic Spec 2.0.2

Requirements that survive a change of stack.

A complete business contract, replaceable architecture, and executable tests before implementation. One atom, one unit of knowledge.

Install the skillMigration to 2.0

Keep the business contract

Rules, concepts and AC must be sufficient to reproduce functionality without reading the old code. IDs preserve meaning across ports.

Replace the architecture

Technologies, component contracts and constraints live in a separate domain. Replace them while preserving the business guarantees.

Gate A — Analysis

Actors, rules, invariants and guarantees without the old code.

Gate B — Gherkin

Stable AC and concrete, observable outcomes.

Gate C — Tests · RED

Real execution before behavior; failure caused by the requirement.

Gate D — Implementation · GREEN

The same tests and affected regressions pass.

After GREEN comes acceptance: requirement → scenario → test → result. Environment errors and skips are neither RED nor PASS. One agent can perform the roles.

Create the link while writing the code
