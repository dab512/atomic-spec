## Intent

Проверки A/B/C/D и приёмка. Требования описывают наблюдаемый контракт методологии Atomic Spec 2.0.

## Domain Rules

### DR-1. Обязательность

Применимые обязательства gate проверяются до следующего этапа. Gate A — аналитика; B — проверяемые AC и архитектурные контракты; C — исполняемые тесты с доказательством RED; D — GREEN и затронутые регрессии.

### DR-2. Полнота доказательства

Ошибка окружения, импорта, отсутствие тестов, skip/xfail и незапущенная проверка не считаются RED либо PASS. Верное существующее поведение сохраняет baseline GREEN.

### DR-3. Отказ и возврат

Непройденный критерий фиксируется вместе с причиной и возвращает работу к ответственному этапу. Для бага RED воспроизводит старую ошибку либо контролируемую мутацию в изоляции.

## Acceptance Criteria

### AC-1. Окружение не RED

```gherkin
Scenario: Окружение не RED
  Given новый тест не импортирует отсутствующую зависимость
  When проверяется Gate C
  Then результат классифицируется как блокер окружения и gate не пройден
```

### AC-2. Приёмка после GREEN

```gherkin
Scenario: Приёмка после GREEN
  Given новые тесты и затронутая регрессия проходят
  When проводится приёмка
  Then фиксируются матрица требований, проектные проверки и непроверенный остаток
```

### AC-3. Существующий GREEN

```gherkin
Scenario: Существующий GREEN
  Given проверяется неизменённое верное поведение
  When тест проходит
  Then baseline GREEN сохраняется без искусственной порчи рабочего кода
```
