## Intent

Бизнес-контракт и заменяемая архитектура. Требования описывают наблюдаемый контракт методологии Atomic Spec 2.0.

## Domain Rules

### DR-1. Разделение

Бизнес-атомы описывают гарантии потребителю; архитектурный домен содержит заменяемые способы их обеспечения и технические ограничения.

### DR-2. Связь

Архитектурный атом называет обеспечиваемые бизнес-ID/DR/BR/AC, область действия, причины выбора, альтернативы и критерии. Код и тесты ссылаются на применимые требования обоих видов.

### DR-3. Перенос

При смене стека сохраняются бизнес-ID, правила и AC, заменяются архитектура, тестовый код и реализация. Изменение бизнес-гарантии классифицируется отдельно.

### DR-4. Технический продукт

Протокол, API или формат может быть внешним бизнес-контрактом технического продукта. Разделение определяется смыслом гарантии и заменяемостью механизма, а не запретом технических слов.

## Acceptance Criteria

### AC-1. Перенос

```gherkin
Scenario: Перенос
  Given бизнес-контракт зафиксирован
  When выбирается новый стек
  Then архитектура заменяется при сохранении бизнес-ID и AC
```

### AC-2. Внешний протокол

```gherkin
Scenario: Внешний протокол
  Given продукт гарантирует потребителю формат протокола
  When описывается бизнес-атом
  Then протокол остаётся в контракте потребителя
```
