## Intent

Жизненный цикл атома. Требования описывают наблюдаемый контракт методологии Atomic Spec 2.0.

## Domain Rules

### DR-1. Шаблон

Бизнес-атом создаётся из бизнес-шаблона; самостоятельное архитектурное решение — из архитектурного. Пустые уровни и технические дубли каждой фичи не обязательны.

### DR-2. Черновик

draft обозначает формируемый контракт. Blocking OQ не позволяет пройти Gate A/B; non-blocking вопрос сопровождается допущением.

### DR-3. Готовность

После проверки сценариев Gate B контракт получает ready. review означает проверку или существенную правку; implemented присваивается только после приёмки объявленной реализации.

### DR-4. Депрекация

deprecated сохраняет ID, причину и связь с заменой. Физическое перемещение не должно рвать реестр и ссылки; удаление истории запрещено.

### DR-5. Идентичность

Именование файлов задаёт проект. Реестр связывает ID с путём внутри spec-root. Изменение имени или каталога не меняет ID и не подтверждает готовность.

## Acceptance Criteria

### AC-1. Готовность без реализации

```gherkin
Scenario: Готовность без реализации
  Given Gate B пройден и реализация ещё не началась
  When фиксируется готовность требований
  Then status становится ready и не заявляет выполненный функционал
```

### AC-2. Смена пути

```gherkin
Scenario: Смена пути
  Given атом переименован
  When обновляется реестр
  Then прежний URI разрешается к тому же ID
```

### AC-3. Неподтверждённая реализация

```gherkin
Scenario: Неподтверждённая реализация
  Given тесты пропущены
  When запрашивается implemented
  Then приёмка остаётся незавершённой
```

## Статусы

Единственная нормативная ось жизненного цикла: draft → review → ready → implemented → deprecated.
При изменении согласованного контракта атом возвращается в review. Для новой реализации
на другом стеке фиксируется её отдельная область; реализованность старой не подтверждает новую.
Необязательные implementation/verification/evidence — проектные записи результатов с scope,
ревизией, командами и результатами. Они не являются второй независимой системой статусов атома.
Legacy active мигрирует в ready; в implemented — только при наличии подтверждённой приёмки.
