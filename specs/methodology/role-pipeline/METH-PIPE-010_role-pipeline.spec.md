## Intent

Роли и порядок работы. Требования описывают наблюдаемый контракт методологии Atomic Spec 2.0.

## Domain Rules

### DR-1. Последовательность

Аналитик формирует контракт (A); Тестировщик уточняет Gherkin (B), пишет и запускает автотесты (C/RED); Разработчик реализует поведение (D/GREEN); Тестировщик проводит приёмку.

### DR-2. Чтение

Каждая роль читает все необходимые бизнес- и архитектурные требования, сценарии и результаты. Ограничение чтения только собственными секциями запрещено.

### DR-3. Запись

Роль меняет артефакты своей ответственности. Противоречие в чужом контракте возвращает работу соответствующей роли с обоснованием; требования не меняются под алгоритм.

### DR-4. Явная ответственность

Переключения объявляются маркером роли. Одного агента достаточно; обязательного делегирования нет. Разрешения на VCS/deploy определяет проект и поручение.

## Acceptance Criteria

### AC-1. Тесты до реализации

```gherkin
Scenario: Тесты до реализации
  Given Gate B пройден
  When Тестировщик приступает к исполняемым сценариям
  Then переход разрешён до написания бизнес-логики
```

### AC-2. Ранняя реализация

```gherkin
Scenario: Ранняя реализация
  Given Gate C не подтвердил RED нового поведения
  When Разработчик пытается реализовать его
  Then работа возвращается к подготовке исполняемых тестов
```

### AC-3. Чтение общего контракта

```gherkin
Scenario: Чтение общего контракта
  Given Разработчику нужна бизнес-гарантия
  When он открывает бизнес-атом
  Then чтение разрешено независимо от авторства атома
```
