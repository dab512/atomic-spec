## Intent

Переносимые живые требования. Требования описывают наблюдаемый контракт методологии Atomic Spec 2.0.

## Domain Rules

### DR-1. Один атом

Один атом — один *.spec.md с устойчивым уникальным ID; предмет атома — самостоятельное требование или решение.

### DR-2. История

Устаревший атом помечается deprecated с причиной и ссылкой на замену. Его ID не переиспользуется. История решения сохраняется в VCS.

### DR-3. Gates

Аналитика, сценарии, RED и GREEN проходят Gate A/B/C/D; приёмка проверяет результаты в объявленной области.

### DR-4. Переносимость

Бизнес-домены и их AC достаточны для воспроизведения функционала без чтения старого кода. Заменяемые решения находятся в архитектурном домене.

### DR-5. Решения

Изменение правила имеет классификацию совместимости, impact и датированное обоснование в Decision Log.

## Acceptance Criteria

### AC-1. Воспроизведение контракта

```gherkin
Scenario: Воспроизведение контракта
  Given бизнес-атомы и AC доступны без старого кода
  When выбран другой стек
  Then поведение однозначно определяется теми же правилами и AC
```

### AC-2. Неполная приёмка

```gherkin
Scenario: Неполная приёмка
  Given один обязательный сценарий не выполнен
  When запрашивается статус implemented
  Then статус не присваивается за пределами подтверждённой области
```
