# Архитектура как заменяемый домен

Архитектура — отдельный домен единой спецификации, а не обязательная техническая
прослойка каждой бизнес-фичи. Атом описывает самостоятельное решение/ограничение,
применимое к одному или нескольким бизнес-доменам. Правила архитектурного домена
могут называть технологии, API, схемы, взаимодействия компонентов и миграции.
Решение должно иметь причину и проверяемые критерии, а не только название технологии.

Бизнес-атомы → независимый контракт поведения.
Архитектурный домен → выбранные способы и ограничения реализации этого контракта.
Код и тесты → ссылки на требования обоих видов.

Используй шаблон assets/architecture-template.spec.md. `satisfies` — явно записанные
связи с бизнес-требованиями; проверяй их смысл и существование вручную. Bundled Guard
не валидирует граф frontmatter satisfies и не доказывает обеспечение бизнес-гарантий
архитектурой. Его доказанные команды связывают исходники с требованиями.

## Перенос

1. Зафиксируй исходный бизнес-контракт: атомы, ID, AC, версию/снимок.
2. Проверь полноту без чтения старого кода как обязательного источника. Если бизнес-
   решение потеряно, оформи вопрос; не подменяй пробел предположением нового стека.
3. Подготовь замену architecture/ для нового стека. Сохраняй прежний набор в истории
   или отдельном spec-root; два варианта одного SPEC-ID не смешивай в одном реестре.
4. Сохрани бизнес-ID и сценарии. Если изменилась бизнес-гарантия, это самостоятельное
   изменение контракта с анализом совместимости, а не «просто перенос».
5. По архитектурным контрактам напиши новый код тестов, подтверди RED, затем реализацию
   и GREEN. Приёмка проверяет тот же бизнес-функционал на новом стеке.

## Миграция старых смешанных атомов

Переноси из Tech Spec и Implementation Notes только нормативные решения в архитектурный
домен. Историю отладки и детали конкретных файлов оставляй в документации реализации.
Domain Model Touch разделяй по смыслу: предметные понятия/инварианты остаются в бизнесе,
программные компоненты и схемы хранения относятся к архитектуре. Не удаляй сведения
до проверки сохранности требований и обновления всех затронутых ссылок.
